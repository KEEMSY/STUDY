# 경험 기반 답변 가이드

3년차 면접에서 기술 지식과 동등하게 중요한 영역.  
"무엇을 했는가"보다 **"왜 그 결정을 내렸는가"**를 보는 질문들이다.

<br>

## STAR 구조

모든 경험 기반 질문의 기본 뼈대.

```
S (Situation)  — 상황: 어떤 맥락이었나? (팀 규모, 서비스 규모, 시점)
T (Task)       — 과제: 내가 해결해야 했던 문제는?
A (Action)     — 행동: 내가 구체적으로 한 것 (기술 선택, 설계, 협업)
R (Result)     — 결과: 수치로 측정된 결과, 배운 점
```

**주의**: Action이 핵심이다. "팀이 했다"가 아니라 "내가 구체적으로 한 것"을 말해야 한다.

<br>

## 자주 나오는 질문 유형과 준비법

### 기술적 의사결정
> "기술 스택을 선택할 때 어떤 기준으로 결정하나요?"  
> "레거시 코드를 리팩토링한 경험이 있나요? 어떻게 접근했나요?"  
> "마이크로서비스 vs 모놀리식 중 어떤 것을 선택하고 왜 그랬나요?"

**준비 포인트**: 선택의 이유 + 포기한 것(트레이드오프) + 결과를 함께 말한다.

---

### 장애 / 문제 해결
> "프로덕션에서 장애가 발생했을 때 어떻게 대응했나요?"  
> "성능 문제를 어떻게 찾아내고 개선했나요?"  
> "예상치 못한 기술적 이슈를 만났을 때 어떻게 해결했나요?"

**준비 포인트**: 당황하지 않고 원인을 추적한 과정 + 재발 방지 대책까지

---

### 협업 / 의견 충돌
> "동료나 다른 팀과 기술적 의견 충돌이 있었나요? 어떻게 해결했나요?"  
> "주니어 개발자를 리드하거나 도움을 준 경험이 있나요?"  
> "마감 압박이 있을 때 기술 부채를 어떻게 다루나요?"

**준비 포인트**: 내 주장을 어떻게 근거로 설득했는지 + 상대방 의견을 어떻게 반영했는지

---

### 성장 / 학습
> "최근 새로운 기술이나 개념을 학습한 경험이 있나요?"  
> "본인의 가장 큰 기술적 실수는 무엇이고 무엇을 배웠나요?"  
> "3년 후 어떤 개발자가 되고 싶나요?"

---

## 경험 정리 템플릿

매일 15분씩 이전 프로젝트 경험을 이 형식으로 정리한다.

---

### 경험 카드 작성법

```
[제목] 어떤 문제를 해결했는가 (1줄 요약)

[상황]
- 서비스: (서비스 성격, 규모)
- 시점: (재직 기간 중 언제)
- 팀 구성: (몇 명, 내 역할)

[문제]
- 기술적 문제: (구체적으로)
- 비즈니스 영향: (이게 왜 중요했나)

[내 행동]
1. 원인 분석: (어떻게 파악했나)
2. 선택지: (A 방법 vs B 방법)
3. 선택 이유: (왜 이것을 골랐나, 트레이드오프)
4. 구현: (구체적으로 무엇을 했나)

[결과]
- 수치: (응답시간 X% 개선, 에러율 X% 감소 등)
- 부가 효과: (팀 프로세스 개선, 재사용성 등)
- 배운 점: (이 경험에서 얻은 것)
```

---

## 준비할 경험 최소 3~5개

3년차라면 이 유형의 경험이 최소 하나씩 있어야 한다:

| 유형 | 내용 |
|------|------|
| **성능 개선** | DB 쿼리 최적화, 캐시 도입, API 응답속도 개선 |
| **아키텍처 결정** | 기술 스택 선택, 설계 패턴 적용, 모듈 분리 |
| **장애 대응** | 프로덕션 이슈 원인 파악 + 해결 + 재발 방지 |
| **리팩토링** | 레거시 코드 개선, 기술 부채 해소 |
| **협업/리드** | 코드 리뷰, 주니어 온보딩, 타 팀과 API 협의 |

## 3년차에서 특히 신경 쓸 것

### "주니어와 뭐가 다른가"를 보여줘야 한다

면접관은 이것을 확인하고 싶어 한다:
- 단순 구현이 아닌 **설계 판단**을 내린 경험
- 기술 결정의 **트레이드오프를 인지**하고 있었는가
- **팀에 기여**하는 방식이 있는가 (코드 리뷰, 문서화, 공유)

### 숫자로 말한다
- "느렸는데 빠르게 했어요" (X)
- "P95 응답 시간이 3초에서 300ms로 줄었어요" (O)

숫자를 기억 못 하더라도 **비율과 맥락**은 말할 수 있어야 한다.

## 역질문 준비 (면접 마지막)

역질문은 "이 회사/팀에 진심으로 관심 있다"는 신호다.

**좋은 역질문 예시**
- "지금 팀에서 가장 큰 기술적 챌린지가 무엇인가요?"
- "온보딩 과정이 어떻게 되나요? 합류하면 처음 몇 달을 어떻게 보낼 것 같나요?"
- "기술 결정을 내릴 때 팀 내에서 어떤 방식으로 논의가 이루어지나요?"

**피해야 할 역질문**
- 연봉, 복지 관련 (이 자리에서 하지 않는다)
- 쉽게 찾을 수 있는 공개 정보 질문
